**Then: per-window tty/pty (the `dir`-in-a-window problem).** The OS already has the seed: `SYS_PUTC`/`OUTCH` ($2009) routes stdout to console-or-file via REDIRF; `< file` (INMODE), pipes (PIPEF, file-backed/sequential). Plan: generalize OUTCH's sink to also be "a window's text buffer" → text commands (dir/cat/wc) render IN a window with ZERO command changes. NO true concurrency needed: switching is the user's EXPLICIT focus change, only at the desktop between commands (a command runs foreground-to-completion; can't switch mid-command). Per-window state carried in the window record: cwd(48B)+line buf(64B)+scrollback(~140B) ≈ 250B/window; SHARE the 2KB history ring + PATH/resolver. The shell is BUILT INTO the OS (SHELL: loop, not a bash/csh binary); `cd/mkdir/rmdir` are builtins, `dir/cat/pwd` are external /bin binaries (de-built-in'd). Requires the resident WM (control must return to it after a command).

**Boot flow MUST stay:** monitor → B → serial-terminal shell (fd0/1/2 = /dev/tty), GUI opt-in via `desk` command (windows = /dev/pty0..N on the card). User was explicit on this.
