`hardware/arduino-scratch/` is a throwaway **workflow probe**, not part of the P8X
machine — it exists to test the Cowork↔Fusion round-trip (generate Eagle files,
open in Fusion, place/route, hand back for edits, reimport, check consistency).

- Circuit: classic "Arduino from scratch" — ATmega328P-PU + 16 MHz crystal +
  reset pull-up + 7805 (in/out caps) + 6-pin FTDI header (DTR auto-reset cap) +
  pin-13 & power LEDs. All through-hole. 76.2×50.8 mm.
- Generated by `generators/gen_arduino.py` — **standalone**: reuses gen_eagle's
  emitters (`write_sch`/`write_brd`/`validate`, `fp_box`, `DEV`/`PKG`) and adds its
  own parts (ATMEGA328/DIP28N, XTAL16/HC49, L7805/TO220, HDR6, HDR2), but NOT
  `card()` (no P8X DIN96 connector). File-writing is guarded under `__main__`, so
  importing it (to reuse device/pad defs) is side-effect-free.
- NOT wired into `build_all`/`check_artifacts` (those are P8X-only).
- Arduino pin map used: D8=PB0=pad14, D13=PB5(SCK)=pad19; LED device pm A=pad2
  (anode), K=pad1 (cathode); RES pm 1=1,2=2.
- Round-trip: Fusion rewrites to Eagle 9.7.0 and expands the files (~1.7x, fuller
  library defs); netlist/parts identical. `-a`-suffixed files are the user's
  round-tripped copies (kept untracked as test scratch).

Once the user has hand-placed/hand-edited in Fusion, the FILES are the truth, not
`gen_arduino.py` (which stays stale — it won't know about hand-added parts). For
ANY downstream work (PDF, BOM, edit, reconcile) DERIVE STATE BY PARSING THE
`.sch`/`.brd`, never from the generator's Python model, and EDIT IN PLACE (never
regenerate — would wipe placement + hand edits).

TRAP: the WHOLE P8X toolchain is generator-driven — `render_traditional_auto`/
`draw_card` (schematic PDF) and `gen_bom.py` (BOM) both read `G.CARDS`, NOT the
`.sch`. Correct for P8X boards (generator IS truth there), WRONG for a hand-edited
board: they silently emit the stale part set and drop hand-added parts. For
arduino-scratch, derive BOM / PDF / netlist by PARSING the `.sch` instead.
(Verified: a file-parsed BOM shows all 21 parts incl. the hand-added R4/R5/LED3/
LED4; gen_bom.py would show the generator's stale 17.)
