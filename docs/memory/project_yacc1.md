**Architecture (from opcodes.h + emulator + microcode generator):**
- 8-bit accumulator (ACC) + 8-bit TMP register; 16-bit index registers R0..R7 (R0=PC, R1=SP by
  convention; hardware supports up to 16 across 4 register cards); carry flag; IN line.
- 64K address space, 8-bit data. MEMORY CARD V1.3 (verified on hardware 2026-09-18 via the bus driver):
  two 62256 (low RAM $0000-$7FFF, hi RAM) + one 28C64 EEPROM (8K, so ROM = $E000-$FFFF, not 32K as the
  README says). Hi half $8000-$FFFF is decoded per 4K block by a 74LS138 into a 3x8 jumper header: jumper
  up = hi RAM, down = ROM, none = undecoded. Current jumpers: $8000-$CFFF RAM, $D000 DELIBERATELY UNDECODED
  (reserved for a future memory-mapped alphanumeric video card), $E000-$FFFF ROM. Reading an undecoded
  block returns the last value on the bus (looks like "RAM that reads back the last write"), not FF.
  Boot remap: 74LS74 FORCE-ROM preset by -RESET forces BADDR12-15 high through a 74LS157, so $F000 ROM
  appears at every address until the first access with ADDR15 HIGH (any A15 access, not only $F000).
  Emulator refuses writes > $DFFF. BASIC image goes at $E000, monitor at $F000 (makerom). The EEPROM
  actually burned (captured 2026-09-18 via the bus driver, 8K) is BYTE-IDENTICAL to
  `Software-vs/Assembler/rom` (= that folder's basic.img + monitor.img, built from the 2021-07-09
  basic.asm/monitor.asm in Software-vs) == git commit ff7d85a 2021-07-10 exactly. Later commits, NEVER
  burned: 8afde21 2021-08-31 (BASIC ON/OFF statements, break into a running program via new BIOS
  vector charavail/e_uarttest at $FFEC, UART LSR data-ready check); 793988f "remove unused code";
  3bcacf3 2021-09-02 "not working needs revert" (= GitHub master HEAD and the newgit/gitversion working
  trees, i.e. the so-called "2025 monitor.asm"; only change vs 8afde21 = comments out a debug dump block
  because ROM overflowed). Local YACC1-2020/2024 master 02041bb reverts both -> back to 8afde21.
  Recommendation for consolidation: chip = ff7d85a (known good); candidate next = 8afde21 (needs a
  hardware test of ON/OFF + break-in); 3bcacf3 is junk.
  BIOS entry vectors at $FFC0.. (stringout/charout/uartout/uartin/charavail...). Stack $0EFF down.
  Monitor vars $0F00-$0FFF, BASIC vars $0100 / $0200.
- 16 I/O ports via OUTA/OUTI/INP; P0 = control/select port (UART CS $40 + reg addr, SWITCHLED $01,
  LCD, TIL311 $80), P1 = data port. Serial is a 16550-style UART behind P0/P1 at 38400.
- ISA: ~90 opcodes, 1-3 bytes, big-endian addresses. Branches BR/BRZ/BRNZ/BRC/BRLT/BREQ/BRGT/BRNEQ
  compare ACC vs TMP. JSR/RET, PUSH/POP, PUSHR/POPR, MVIB/MVIW, LDAVR/STAVR (indirect via Rn), INCR/DECR,
  LDR/STR Rn,addr, ALU imm+TMP forms, shifts, INTE/INTD/IRET/IADDR. No 16-bit ALU, no indexed+offset.
- Microcode: 64 steps x 8 bytes per opcode, generated by C (`uCode-Generator2`), loaded into sequencer
  card EEPROM/RAM by an Arduino (`Sequencer3.ino`).

**Toolchain:** RC/asm v2.2 (Michael Riley) table-driven assembler in C, `yacc1.def` defines the ISA;
Intel-hex output; `makerom` builds rom from basic.img+monitor.img. C emulator `emulator/main.c`
(single file, ~1300 lines, stdin/stdout console on port 2 / UART on P0=$40,P1). ubasic (Adam Dunkels)
modified interactive, exists as C AND as hand asm `basic.asm` (3167 lines). Monitor `monitor.asm`
